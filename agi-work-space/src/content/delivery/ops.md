OP 维护。本工程是纯前端，构建结果只有静态 `dist/`，没有应用服务器。发布 = 上传静态包；回滚 = 换回上一包或 git 回滚后重建。

## 环境

| 环境 | 地址 | 用途 | 谁可以发 |
| --- | --- | --- | --- |
| 本地 | `npm run dev` | 开发 | 全员 |
| 预览 | `npm run preview` / 测试机 | 验收 | OP / QA |
| 生产 | （填写） | 正式访问 | OP |

## 发布

1. 确认 QA 门禁已勾，证据在 [执行证据](/quality/evidence)
2. `npm run build`
3. 上传 `dist/`
4. History 路由需把未知路径回退到 `index.html`
5. 打开首页与一篇深路径文档做冒烟
6. POM 更新 [项目状态](/project/status)

## 监控与告警

| 指标 | 如何看 | 阈值 | 通知谁 |
| --- | --- | --- | --- |
| 站点是否可打开 |  | 5 分钟不可访问 | OP / POM |
| 静态资源 404 |  | 核心 JS/CSS 失败 | OP |

## 应急

| 现象 | 判定 | 动作 | 沟通 |
| --- | --- | --- | --- |
| 页面空白 / 静态资源 404 | 发布包不完整 | 回滚上一包 | 通知 POM |
| 保存无法写回 | 浏览器权限 | 让用户到配置中心重新授权，不回滚站点 | 通知 FE 若是缺陷 |
| 误发错误文档 | 内容事故 | 回滚仓库对应提交或重新发布 | 通知 PM / POM |

值班人：  
升级时限：15 分钟无进展 → POM

## 回滚

- **触发条件：** 主路径不可用、错误内容已对外、门禁事后发现 P0
- **步骤：**
  1. 停发新包
  2. 重新发布上一稳定 `dist/` 或 git 回滚后构建
  3. 冒烟 TC-01～TC-03
  4. 写入 [项目决策](/records/decisions) 或状态页「近期变更」
