终端用户角色、典型场景，以及需求编号 **REQ-***（与用例、任务对齐）。功能规则以 [PRD](/product/spec/prd) 为准。

## 用户是谁

| 角色 | 他们想要什么 |
| --- | --- |
| 访客 | 随便逛逛，愿意就注册 |
| 创作者 | 发笔记、用 AI 改文案、看互动 |
| 浏览者 | 刷 Feed、搜索、收藏 |
| 爱聊天的人 | 私信、分享笔记给好友 |
| 直播主 | 开播，让观众能看 |
| 被关注的人 | 主页好看、数据清楚（粉丝、获赞等能点进去看） |

## 我们解决什么痛点

- 生活记录分散 → 用笔记流 + 个人主页收拢  
- 写文案难 → 发帖时 AI 润色  
- 找不到看过的东西 → 搜索、收藏、浏览历史  
- 互动太乱 → **通知**（系统提醒）和 **私信**（聊天）分开

## 典型场景（故事版）

**注册登录** — 用手机号或 GitHub 登录，留在网站里不用反复登。

**刷笔记** — 在关注/发现里翻，点进详情，顺手赞或评论。

**发帖** — 传图或视频，可选用 AI 改标题正文，发布后出现在主页和流里。

**被互动** — 有人赞我、评我、@我、关注我 → 只在 **通知** 里出现，不进私信。

**私聊** — 在 **消息** 里和好友聊，也可以把一篇笔记发过去当卡片。

**看主页** — 点一页号进主页，看 TA 的笔记；点「粉丝」「获赞」等数字进列表。

**直播** — 主播开播，观众从列表点进去用 HLS 看。

**举报** — 对违规笔记或用户提交举报。

每个场景在 PRD 里都有对应模块和验收项。
