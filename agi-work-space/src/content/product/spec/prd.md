## 摘要

ONEPAGE 是 **PC 端生活方式社区**（记录生活每一页），加上 **AI** 与 **基础直播**。

请记住：**通知** 和 **私信** 分开；MVP **不做** 礼物、连麦带货、复杂推荐、原生 App。登录用 **Cookie 会话**。

## 产品里有哪些主界面

PC **侧栏文案**以 [视觉规范](/design/system/specs) 为准（首页、耶耶、视频、直播、发布、通知、消息、我的；底栏更多 / 关于我们）。下表是能力分组，不是导航标签。

| 能力 | 里面有什么 |
| --- | --- |
| 首页 Feed（发现 / 关注 Tab） | 刷笔记、看详情 |
| 发布 | 写笔记、传媒体、可选 AI 改文案 |
| 搜索 | 壳已有展开面板（历史+直播/话题）；全文检索 P3 |
| 消息 | **通知** 与 **私信** 分入口（侧栏两项） |
| 直播 | 列表与直播间（P4）；壳有入口 |
| 耶耶 | AI 助手（P3）；壳有入口 |
| 我的 | 资料与设置 |
| TA 的主页 | 用「一页号」访问 |

## 功能模块

### A. 账号与登录（P0）— REQ-A*

| 功能 | 说明 | 规则与边界 |
| --- | --- | --- |
| 手机号注册/登录 | 短信验证码 | 验证码有效期、发送频率限制（Redis）；未注册手机号验证通过可自动注册；提交前须同意《用户协议》《隐私政策》 |
| 账密注册/登录 | 用户名/邮箱+密码 | 密码 BCrypt 存储；建议 MVP 注册后引导绑手机 |
| 第三方登录 | GitHub、Google OAuth | 授权后创建或绑定账号，写入统一 Session |
| 登出 | 清除服务端 Session | Cookie 失效；全端登出 |
| 找回密码 / 设置密码 | 短信找回；已登录设密或改密 | 短信开户无密码须在「我的」设置；找回仅已有该手机号的账号；密码 8～32 位且含字母和数字 |

**不做（MVP）**：微信/苹果登录、多端 Token API。

### B. 笔记（内容）（P1）— REQ-B*

| 功能 | 说明 | 规则与边界 |
| --- | --- | --- |
| 笔记类型 | 图文、纯文、视频 | 至少支持：多图（上限 PM 定，建议 ≤9）、单视频（大小/时长上限实施时定） |
| 编辑发布 | 标题+正文+媒体 | 发布前媒体先传 MinIO（预签名）；发布失败不展示为已发布。已发布笔记可在创作者中心改内容（`PATCH /posts/{id}`），须为作者 |
| Feed | 发现、关注 | 关注流：已关注用户的已发布笔记；分页 cursor |
| 详情 | 全文、作者、互动区 | 记录浏览历史（登录用户，仅自己可查列表） |
| 草稿 | 可选 | MVP 可后置；若做则仅作者可见 |
| AI 美化文案 | 一键优化标题/正文 | 调用 ai-service；超时/失败允许原样发布 |

### C. 互动（P1）— REQ-C*

| 功能 | 说明 | 规则与边界 |
| --- | --- | --- |
| 点赞 | 笔记级 | 同一用户对同一笔记仅一条；可取消 |
| 收藏 | 笔记级 | 同上；出现在「我的收藏」 |
| 评论 | 多级 | `parent_id` 树形；MVP **展示建议 2 层**（一级评论+回复），更深折叠「展开更多」 |
| 评论点赞 | 评论级 | 独立计数 |
| @ 用户 | 评论内 @ | 解析一页号或昵称；被 @ 用户收到**通知** |
| 分享-链接 | 复制外链 | 链接打开笔记详情（权限：公开笔记） |
| 分享-私信 | 发送笔记卡片 | 走 message-service，类型 `POST_CARD` |

### D. 用户与关系（P1–P2）— REQ-D*

| 功能 | 说明 | 规则与边界 |
| --- | --- | --- |
| 一页号 | 对外用户 ID | 注册时生成，**不可修改**；用于 URL `/u/{pageId}` |
| 资料 | 头像、封面、签名、性别 | 图片走对象存储；敏感词策略 P5 可加 |
| 关注 | 关注/取关 | 单向关注；产生「新关注」**通知** |
| 统计展示 | 关注数、粉丝数、获赞与收藏数 | 展示在个人主页；**点击数字进入对应列表页** |
| 列表页 | 关注列表、粉丝列表、获赞列表、被收藏列表 | 分页；头像+一页号+昵称 |
| 个人内容 Tab | 笔记、收藏、赞过 | 自己主页全量；他人主页仅公开笔记（收藏/赞过 MVP 可仅自己可见） |
| 浏览历史 | 看过的笔记 | **仅本人**可见列表（已接 `GET /users/me/history`）；单条删除或清空尚未做 |

### E. 通知与私信（P2）— REQ-E*

**原则：通知 ≠ 私信。两个入口、两套数据、两套未读数。**

| 类型 | 归属 | 触发示例 |
| --- | --- | --- |
| **通知** | notification-service | 评论我的笔记、回复我的评论、@ 我、赞/藏我的笔记、新关注 |
| **私信** | message-service | 用户之间单聊文本/图片/笔记卡片/直播卡片 |

| 功能 | 说明 | 规则与边界 |
| --- | --- | --- |
| 通知列表 | 时间倒序 | 未读/已读；聚合键去重（同帖多次赞可合并策略 PM 可选） |
| 私信会话 | 单聊 | 会话列表按最后消息时间排序；未读游标 |
| 实时 | WebSocket 优先 | 握手带 Session Cookie；离线拉历史 REST |
| 铃铛/角标 | shell 展示 | 通知未读、私信未读**分开**显示 |

### F. 搜索与 AI（P3）— REQ-F*

| 功能 | 说明 | 规则与边界 |
| --- | --- | --- |
| 全局搜索 | 笔记、用户、话题、直播 | 壳路由 `/search`；ES 全文分页（P3）；P0 为占位 UI |
| AI 助手 | 搜索页耶耶摘要 + 耶耶页问答 | RAG：search 检索 + ai 生成；不编造无依据链接 |
| 发帖 AI | 见 B | 仅润色，不自动发布 |

### G. 直播（P4，基础）— REQ-G*

| 功能 | 说明 | 规则与边界 |
| --- | --- | --- |
| 创建房间 | 标题、封面可选 | 绑定当前用户 |
| 开播/关播 | 状态机 | 直播中才出现在列表 |
| 推流 | RTMP 等 | 向主播展示推流地址与说明 |
| 观看 | HLS | 观众端播放器；在线人数 Redis 近似值 |
| 直播列表 | 正在直播 | 按开播时间排序 |
| 直播间聊天 | 可选 MVP | 独立 topic 或简版弹幕；不与私信混 |

**不做（MVP）**：礼物、连麦、带货、录制回放管理台。

### H. 举报与治理（P5）— REQ-H*

| 功能 | 说明 | 规则与边界 |
| --- | --- | --- |
| 举报笔记 | 原因+说明 | 提交后 moderation 入库 |
| 举报用户 | 原因+说明 | 同上 |
| 入口 | 笔记详情、用户主页 | 需登录 |
| 处理 | 运营后台治理台 | 独立站 `apps/app-ops`（:5176）。工作台全站数字；治理工单/用户/私信巡查；内容笔记/评论/媒体库/分类/活动/话题 CRUD。列表表格+分页。直播搜索 AI 未上线不进菜单（DEC-038～041）。 |

## 业务流程（端到端）

```text
注册/登录 → 浏览 Feed/搜索 → 详情（赞藏评/分享）
                ↓
            发帖（媒体+AI）→ 发布 → 异步索引/通知粉丝（可选）
                ↓
关注用户 → 关注流 + 新关注通知
                ↓
评论/@ → 通知中心；私信 → 消息中心
                ↓
开播 → 列表 → 观众 HLS 观看
                ↓
举报 → moderation 记录
```

## 验收标准（MVP 发布门禁）

### 账号
- [ ] REQ-A1～A4：短信、账密、GitHub/Google、登出

### 笔记与 Feed
- [ ] REQ-B1～B2：图文视频发布与 Feed/详情
- [ ] REQ-B3：AI 美化可跳过

### 互动
- [ ] REQ-C1～C3：赞藏、多级评论与评赞、链接分享
- [x] REQ-C4：私信分享卡片（`POST /posts/{id}/share/im`，`post_card`）

### 用户与关系
- [ ] REQ-D2：资料与一页号不可改
- [x] REQ-D1、D3、D4：关注、我的 Tab 与历史、获赞/被收藏列表（仅作者）

### 消息
- [x] REQ-E1：通知分栏、未读、赞评关注投递、评论 @ 解析（一页号或昵称）
- [x] REQ-E2：私信基本收发（HTTP 文本/图片 + 笔记卡片 + `WS /ws/im`）

### 搜索与 AI
- [ ] REQ-F1、F2：搜索与助手问答

### 直播
- [ ] REQ-G1：开播、列表、HLS 观看

### 治理
- [x] REQ-H1、H2：举报提交与入口；运营工单/用户/笔记/评论/媒体库/目录/私信巡查（隐藏走 `deleted_at`）
