ONEPAGE 的产品边界与 MVP 范围（比 [PRD](/product/spec/prd) 更短，不展开每条规则）。

## 一句话

PC 端生活方式社区 — **记录生活每一页**（*Every Day, A New Page*），带 AI 和基础直播。

## 和本工作空间的关系

- **用户用的网站**：将来在 `OnePage-web` + `OnePage-Server` 里做。  
- **你现在打开的 agi-work-space**：给团队放 PRD、架构、接口文档，**不是**产品站本身。

## MVP 做哪些（清单）

| 方向 | 包含 |
| --- | --- |
| 账号 | 短信、账密、GitHub/Google 登录 |
| 内容 | 图文视频笔记、Feed、AI 润色 |
| 互动 | 赞、藏、多级评论、分享 |
| 关系 | 关注、个人主页、各类数字列表 |
| 消息 | **通知** 与 **私信** 分开 |
| 智能 | 搜索、AI 问答 |
| 直播 | 推流 + HLS 观看（无礼物） |
| 治理 | 用户举报 + P5 薄运营后台（`app-ops`，不是完整 CMS） |

细节规则见 [PRD](/product/spec/prd)。

## 明确不做（MVP）

礼物、连麦、带货、复杂推荐、原生 App、**完整**运营后台（推荐位/复杂 CMS）、在工作空间里做业务 API。P5 允许薄的内部运营后台处理举报。

## 怎样算 MVP 成功

与 [PRD 验收清单](/product/spec/prd#验收标准mvp-发布门禁) 一致：用户能登录、发帖、互动、收通知、私信、搜/问 AI、看直播、能举报；文档与后续 OpenAPI 一致。

## 工作空间本身

七角色文档、本地写回 — 给**团队**用，给 Agent 读上下文。成功标准：角色能勾选写文档，新人能从 [首页](/) 找到 PRD 和架构。
