工作空间文档要**读起来顺**；Agent 与人工共用同一套结构，避免堆术语、无导语的大表。

## 每篇文档建议结构

1. **开头一两句**：直接写**这篇管什么**（不要写「这篇给谁看」、不要只写「XX 维护」）。
2. **快速入口**：TIP/NOTE、步骤或「先看哪几节」，方便跳转。
3. **正文**：短段落讲清概念，再补表格或列表；不要一上来就是大表。
4. **细节下沉**：字段、路径放 [API 明细](/engineering/process/api-endpoints)、[库表](/engineering/tech/database-schema) 等专文，主文档只链接。

## 表格怎么用

| 适合用表 | 不适合用表 |
| --- | --- |
| 对照、枚举、一眼比多项 | 整段说明、流程、原因 |
| 列数 ≤ 4，行不宜超过 15 行 | 把 API 字段拆成几十行宽表（用分组标题 + 小表） |

表头用**人话**（「做什么」而不是只写英文标识）。同一事实只维护**一篇事实源**，别处链接。

## 语气

- 用「你」或「团队」，少用「用户侧」「实施时」堆砌。
- 英文技术名第一次可带中文括号，后文可简称。
- 决策附带**为什么**一两句，不只列选型。

## Agent 写文档时

- 改产品事实：先改 PRD / 路线图 / 契约，再改首页摘要。
- 一篇 MD 一个主题；过长则拆文件并互相链接。
- 动到契约或表结构：同步 [工程规范](/engineering/process/conventions) 检查清单。
