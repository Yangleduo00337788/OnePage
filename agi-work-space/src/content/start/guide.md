第一次使用本工作空间按本页做。任意已勾选角色都可以改本页。当前项目是什么见 [项目介绍文档](/start/project-intro)；为什么这样设计见 [AGI-WorkSpace 新范式](/start/paradigm)。

## 环境要求

- 建议 **Chrome 或 Edge**（写回本地目录用 File System Access）
- 本机已克隆本仓库，能跑 `npm install` 与 `npm run dev`
- 需要推远程时：GitHub / Gitee / GitLab 仓库地址和个人令牌

其它浏览器可以读打包进来的文档，但不能授权目录、不能保存到磁盘。

## 第一次打开

1. 在项目根目录执行 `npm run dev`，用 Chrome / Edge 打开预览
2. 到 [配置中心](/settings) **勾选你的角色**（可多选，可写范围是并集）
3. **授权本机项目根目录**（目录里必须有 `src/content`）
4. 到 [配置中心 · 工作空间标识](/settings#brand) 更换名称、Logo、口号（会写进仓库）
5. 需要把改动交到远程时，再绑定代码空间（仓库地址、分支、令牌）

未勾选角色：全部只读。未授权目录：能读构建时带上的文档，保存会失败。

## 界面怎么用

| 位置 | 做什么 |
| --- | --- |
| 左侧 | 文档树。开始阅读含项目首页；下面是项目总览 / 产品设计 / 体验设计 / 研发设计 / 质量保障 / 交付运维 / 过程记录。底部是空间配置 |
| 首页 | Logo、slogan、介绍；下方「开始阅读」树与左侧同层级 |
| 右侧 | 当前文档真实数量（不含空间配置）+ 本页小标题 |
| 顶栏 | Logo 回首页、面包屑、搜索、空间配置、语言、主题 |
| 搜索 | `Ctrl` / `Cmd` + `K` |

建议阅读顺序：[项目首页](/) → [项目介绍](/start/project-intro) → [新范式](/start/paradigm) → 本页 → 你角色的分类。

## 权限（谁能改什么）

| 范围 | 规则 |
| --- | --- |
| 未勾选角色 | 全部只读 |
| [开始阅读](/start)（含 [项目首页](/)） | 任意已选角色可读可改 |
| `src/content/space/` | 任意已选角色可改；这一组不进「文档目录」树 |
| 其它分类 | 只改所选角色负责的 slug（并集）；其它仍可读 |
| 项目首页文件 | 可改，**不能删** |

侧栏里不属于你的目录会略淡；开始阅读和首页在勾了角色后应与自己的目录一样清晰。

## 怎么改一篇文档

1. 打开有「可维护」标记的文档，点 **编辑**
2. 在预览里改标题、段落、列表、表格；不必手写 Markdown
3. 可粘贴或插入图片，文件落到该文档目录的 `assets/`，正文用相对路径
4. **保存**。若已授权目录，会写回 `src/content/` 对应文件
5. 需要给远程：到配置中心提交推送（按 `.gitignore` 提交整仓）

## 怎么新建 / 删除

- **新建：** 点「新建文档」。文件名只用英文、数字、下划线和连字符。勾选「作为目录」会生成 `index.md`
- 写到当前角色能维护的父目录；在开始阅读下新建则谁勾了角色都可以
- **删除：** 有权限且不是受保护文档时显示删除。首页不可删
- 不要为新文档去加 Vue 路由

## 怎么交给仓库

1. 配置中心绑定代码空间：提供商、仓库、分支、令牌（令牌只存在本机，禁止提交）
2. 填写提交说明并推送
3. 现阶段**没有**应用内 pull / 合并冲突。拉代码、解冲突用 Git 客户端或 IDE

令牌文件是仓库根目录 `.agi-workspace.local.json`，已在 `.gitignore`。

## 给 Agent 的用法

改代码或文档前让 Agent 先读根目录 `AGENTS.md`（与 [Harness 里的 AGENTS.md](/space/harness/AGENTS) 正文同步）。保存 Harness 那一份时，应用会同步根目录副本。不要让 Agent 把业务事实只写在聊天里。

## 常见问题

| 现象 | 先检查 |
| --- | --- |
| 没有「编辑」 | 是否勾选角色；是否属于该角色目录或开始阅读 / 空间配置 |
| 保存失败 / 提示去配置中心 | 是否授权了含 `src/content` 的项目根目录；Chrome / Edge 是否仍持有权限 |
| 侧栏和磁盘不一致 | 授权后把窗口切到后台再回来，会重新扫描；或保存一次触发同步 |
| 推送失败 | 令牌范围、分支名、仓库地址、网络；不要把令牌写进 Markdown |
| 图片不显示 | 是否已授权目录；相对路径是否在该文档的 `assets/` |
| 首页颜色发淡 | 未勾选角色时非自己的目录会淡；勾任意角色后开始阅读应变正常 |
| 想加一篇文档 | 优先在应用内新建；或手加 `.md` + frontmatter，新分类加文件夹和 `index.md` |

## 日常最小闭环

1. 勾角色、授权目录（每人做一次）
2. 当天只改自己职责内的 MD，结论写入 [项目决策](/records/decisions)
3. 需要共享时推送代码空间
4. 阶段变化时改 [项目状态](/project/status) 和 [项目介绍文档](/start/project-intro)
